# Gemini and Antigravity Worked Case

This case shows how a coding-CLI account becomes a Gemini-compatible API while keeping the provider layer separate from the proxy layer. The exact flags and model IDs belong to one point in time; confirm them against the installed proxy build and the account's live model list.

## Route Selection

| Route | Upstream credential | Best for | Important limit |
| --- | --- | --- | --- |
| Antigravity OAuth | Google account with Antigravity access | Reusing a coding IDE or CLI subscription as an API | Loopback callback; account quota and model catalog depend on the plan |
| Gemini API key | AI Studio or Google AI API key | Stable server-side use with a documented API key | Billing and quota follow the API key, not a CLI subscription |
| Vertex AI service account | Google Cloud project and service account | Enterprise projects, regional routing, IAM control | Requires project, region, roles, and API enablement |
| Gemini CLI OAuth | Gemini CLI Google account | Reusing a Gemini CLI login | Availability and flag names vary by proxy release; verify before relying on it |

Choose the route from the credential the user actually owns. Do not convert an API-key task into an OAuth task or the reverse; the quota, billing, and terms differ.

## Antigravity OAuth

### Login Command

```bash
<install-dir>/cli-proxy-api --antigravity-login --no-browser -oauth-callback-port <callback-port>
```

- The default callback port in recent builds is `51121`. The override flag is useful when the port is occupied or blocked.
- `--no-browser` prints the authorization URL instead of trying to launch a browser, which is the right mode on a headless host.
- The login process starts a one-shot callback listener and prints an `accounts.google.com` authorization URL.
- The process has a finite lifetime, commonly five minutes. Generate a fresh URL if it expires.

### Headless Completion

Use one of these paths:

1. **SSH local forward**: on the machine with the browser, run `ssh -L <callback-port>:127.0.0.1:<callback-port> <user>@<proxy-host>`, open the printed URL, and approve. The provider redirects to the forwarded loopback port and the proxy receives the code directly.
2. **Full callback paste**: approve the URL on any machine, copy the complete `http://localhost:<callback-port>/oauth-callback?code=...&state=...` URL from the address bar, and paste it into the login prompt. The URL must carry both `code` and `state`; a bare authorization code fails when state validation is enabled.
3. **Device flow**: not all Antigravity or proxy builds expose one. When a device-code login exists for the provider, prefer it on headless hosts.

Operational details:

- Do not probe the `/oauth-callback` path with `curl`. The handler is one-shot and an empty request can be consumed as the callback, aborting the login.
- A `404` on `http://localhost:<callback-port>/` is normal when only the callback path is registered. It is a useful tunnel check, not a failure.
- The callback URL is tied to the state generated by the current login process. A URL from an earlier attempt produces an invalid-state error.
- Token exchange is a separate outbound request. If the host cannot reach the provider directly, set `HTTP_PROXY`, `HTTPS_PROXY`, and `NO_PROXY` before starting the login command. The same environment must be present on the long-running proxy.
- If the provider rejects an overridden port with `redirect_uri_mismatch`, use the provider's default callback port.

### Credential Persistence

A successful login writes a per-account file into the proxy's auth directory, commonly named `antigravity-<account>.json` with mode `600`. Recent releases watch the auth directory and reload new credentials without a restart. Confirm the reload in the proxy log before debugging the endpoint.

Run the login again for each additional account. Do not copy another machine's credential file as a shortcut; use the supported OAuth flow so refresh tokens remain valid.

## Gemini API Key Route

Configure the key as an upstream credential in the proxy, not as a downstream client key:

```yaml
gemini-api-key:
  - api-key: "<upstream-gemini-api-key>"
    base-url: "<compatible-base-url>"   # optional; omit for the official endpoint
    headers:                            # optional
      <Header-Name>: "<value>"
    proxy-url: "<proxy-url>"            # optional per-key egress
```

For the official Gemini API, set only `api-key`; the proxy supplies the official base URL. Set `base-url` only for a genuinely Gemini-compatible third-party endpoint. Per-key headers apply to the overridden endpoint and should not be used for secrets that must not leave that endpoint.

## Vertex AI Route

Import a service-account key with the build's Vertex import flag, commonly:

```bash
<install-dir>/cli-proxy-api -vertex-import <service-account.json>
```

Add a model-name prefix when the build exposes `-vertex-import-prefix` and the deployment needs to distinguish Vertex models from other Gemini routes. The Google Cloud project must have the relevant API enabled, the service account must have the required roles, and quota is project-scoped. Mount the JSON key read-only and do not commit it.

## Model Discovery

```bash
curl -s -H "x-goog-api-key: <client-key>" \
  http://<proxy-host>:<api-port>/v1beta/models
```

A Gemini-shaped entry contains fields such as:

```json
{
  "name": "models/<model-id>",
  "displayName": "<human-readable name>",
  "description": "<description>",
  "supportedGenerationMethods": ["generateContent"],
  "supportedInputModalities": ["text", "image"],
  "supportedOutputModalities": ["text"]
}
```

- Use the exact ID from the list. The routing layer commonly accepts both `models/<model-id>` and the bare `<model-id>`, but verify with the installed build.
- The display name is not the model ID.
- An Antigravity account can expose more than Gemini models; the same proxy may list Claude or other provider entries with a different `owned_by` hint. Route them through the protocol that supports them.
- Model catalogs are account-specific. Do not hardcode a list from another account or an older date.

The unified OpenAI-shaped list is also available:

```bash
curl -s -H "Authorization: Bearer <client-key>" \
  http://<proxy-host>:<api-port>/v1/models
```

## Gemini-Native Calls

Authentication accepts `x-goog-api-key`, `Authorization: Bearer <client-key>`, or a `?key=<client-key>` query parameter, depending on the build. Prefer a header so keys do not appear in URLs and logs.

### Generate Content

```bash
curl -s -X POST \
  "http://<proxy-host>:<api-port>/v1beta/models/<model-id>:generateContent" \
  -H "x-goog-api-key: <client-key>" \
  -H "Content-Type: application/json" \
  -d '{
    "contents": [
      {"role": "user", "parts": [{"text": "Return a short greeting."}]}
    ],
    "generationConfig": {"maxOutputTokens": 64}
  }'
```

A successful response is Gemini-shaped: `candidates` contain `content.parts`, `finishReason`, and optional thought signatures; `usageMetadata` reports prompt, candidate, and thought token counts.

### Stream Content

```bash
curl -sN -X POST \
  "http://<proxy-host>:<api-port>/v1beta/models/<model-id>:streamGenerateContent?alt=sse" \
  -H "x-goog-api-key: <client-key>" \
  -H "Content-Type: application/json" \
  -d '{"contents":[{"parts":[{"text":"Count to three."}]}]}'
```

Streaming should produce SSE events and terminate cleanly. A reverse proxy in front of the API must not buffer the stream.

### Other Gemini Actions

The route family also commonly exposes token counting and interaction-style calls, for example `:countTokens` and `/v1beta/interactions`. Availability depends on the build; check the proxy's route documentation or probe with the client that will actually use it.

## OpenAI-Compatible Calls

The same account can usually be consumed through the OpenAI surface, which is useful for clients that do not speak Gemini natively:

```bash
curl -s -X POST http://<proxy-host>:<api-port>/v1/chat/completions \
  -H "Authorization: Bearer <client-key>" \
  -H "Content-Type: application/json" \
  -d '{
    "model": "<model-id>",
    "messages": [{"role": "user", "content": "Return a short greeting."}],
    "max_tokens": 64
  }'
```

Use the model IDs from `/v1/models`; do not assume that every Gemini-native ID is routed through the OpenAI surface without verification.

## Google GenAI SDK

For the Python `google-genai` SDK, point the client at the proxy host root and pass the proxy client key as the API key. The SDK normally appends the API version path itself:

```python
from google import genai
from google.genai import types

client = genai.Client(
    api_key="<client-key>",
    http_options=types.HttpOptions(base_url="http://<proxy-host>:<api-port>"),
)

models = [model.name for model in client.models.list()]
response = client.models.generate_content(
    model="<model-id>",
    contents="Return a short greeting.",
)
print(models)
print(response.text)
```

If a client treats the base URL literally rather than appending the version path, set the base URL to the exact prefix that client expects, such as `http://<proxy-host>:<api-port>/v1beta`. Verify with one real call instead of assuming.

## Verification Checklist

- The login process wrote a credential file into the auth directory with owner-only permissions.
- The proxy log shows the credential was loaded or reloaded.
- `GET /v1beta/models` returns a non-empty list that matches the account's entitlements.
- `POST .../<model-id>:generateContent` returns text and a `finishReason`.
- `POST .../<model-id>:streamGenerateContent?alt=sse` streams and terminates.
- The OpenAI-compatible route works if the client depends on it.
- A request without a client key is rejected.
- A restart preserves the credential and the outbound proxy environment.

## Troubleshooting

- **Browser says login succeeded but the model list is empty.**
  - If the credential file exists, then check file permissions and the reload log; restart the proxy if the watcher did not load it. If no file exists, then the token exchange did not complete.
- **Callback root returns 404.**
  - If the root path is not registered, then this is expected; verify the tunnel against the callback path and use the full callback URL.
- **Callback rejected as invalid state or missing code.**
  - If the URL comes from an earlier login attempt, then restart the login and use the current URL; paste the complete callback URL including `code` and `state`.
- **Token exchange times out.**
  - If direct egress is blocked, then set `HTTP_PROXY`, `HTTPS_PROXY`, and `NO_PROXY` before launching the login and restart the login process.
- **`redirect_uri_mismatch` from Google.**
  - If the OAuth client pins its redirect URI, then use the default callback port instead of an override.
- **404 on `generateContent`.**
  - If the model is not in the live list, then copy an exact ID from `/v1beta/models` and confirm the model is routed through the Gemini surface.
- **401 from the proxy.**
  - If the request uses the upstream Gemini API key, then replace it with a proxy client key; upstream keys belong in `gemini-api-key` configuration.
- **Generation works but tools or images fail.**
  - If the model's modality fields do not include the requested input or the proxy's translator lacks support, then switch models or use the protocol the client supports; do not assume text support implies full modality support.

## Quota and Terms

Antigravity and Gemini CLI routes reuse a subscription account, while the Gemini API key and Vertex routes consume API billing or project quota. The proxy cannot increase entitlement. Confirm the account owner's plan permits API-style use and disclose that automated or multi-user access may have different limits from interactive CLI use.
